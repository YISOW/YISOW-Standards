# YISOW 应用图标设计语言与三端交付规范

**YISOW Icon Design Language (YISOW-IDL) V0.1｜审阅稿｜2026-10-23**

> 这是由已认可的四款应用图标建立的 **App Icon 专项视觉规范**，属于拟纳入更大艺术风格规范的子模块。未经明确批准，不直接升级为 ADS-001、ADS-002 的正式条款，不自动覆盖任何项目现有的已批准图标与 App 身份。

## 01. 设计起点与决策链

1. 现有品牌图标中，语匣与缄桥有更强的家族共同性；归屿早期偏小插画；Codex 核镜早期偏强对比工具感。
2. 用户希望保留深青蓝与青绿色关系，但认为深色过重。第一版修正尝试左上角局部提亮，用户认为该炫光突兀。
3. 第二版取消局部耀斑，改用自然平滑、覆盖更广的渐变，使亮度提高但底板不变成发光塑料按钮；语匣和缄桥视觉方向得到认可。
4. 归屿保留“个人文件归处”的核心隐喻，选择文件夹中叠入海湾与太阳的方案；Codex 核镜保留数据三柱，选定观察环/放大镜方案。
5. 形成设计原则：**一致的视觉语法 + 不同的项目隐喻**。不强迫所有主体轮廓相似，更不牺牲产品语义换取完全统一的模板。

## 02. 定义与边界

- 目标气质：冷静、可信、柔和、清爽、现代、可持续识别。
- 核心结构：统一的深青蓝圆角方形视觉容器 + 中心主体符号 + 克制的半扁平材质。
- 设计方法：先语义、再剪影、再负空间、最后材质；先验证 24px 识别，再打磨大图细节。
- 不属于本规范：应用内部按钮、插画、网页营销海报、系统通知的小型功能图标。它们可以继承色系，但有独立尺寸和平台要求。

### 03.1 渐变与照明

底板允许从略亮的蓝青色自然过渡到深海青蓝；亮度变化要沿宽阔区域平滑发生，不可在左上角添加单点强光、星芒、眩光/炫光或与实际造型无关的发光贴片。主体允许少量沿结构边缘的柔光、内阴影与接触阴影，以解释层次而非夺取注意力。避免大面积纯黑导致“闷”。

### 03.2 安全区与尺度（家族设计建议）

- 先按 1024 × 1024 逻辑画布构图，确保主体清晰、均衡、不贴边；建议主体占中心可用区域约 64–76%，复杂文件夹可适当缩小。
- 高亮结构以一级主体为核心，辅助语义必须随尺寸下降而允许删除；在 24px 的可辨认性优先于 1024px 精密视觉。
- 特别注意 **不要把导出图片中的圆角底板当作所有平台必需提前裁剪**。Apple 和 Android 系统可自己裁剪形状。

### 03.3 禁止项

- 禁止突然出现的左上角局部炫光、强镜面、复杂玻璃和金属、夸张 3D 挤出。
- 禁止把应用图标变成复杂产品功能拼贴（放大镜+云+盾+三国旗+齿轮等）。
- 禁止未获批准擅改中心已认可符号、产品名或软件标识。
- 禁止拿截图的白底整体直接缩成应用图标：必须去除画布、说明文字与外部装饰背景。

## 05. Windows / macOS / Android：交付规则

### Windows — 传统 EXE / Win32

- 使用包含 **16/24/32/48/64/128/256px** 的多图像 `.ico`；其中至少 16/24/32/48/256 可覆盖主要场景，64/128 为兼容与缩放储备。
- 检查任务栏、资源管理器、开始菜单、标题栏以及 100–400% 显示缩放；小尺寸可绘制专用优化稿。
- 本包包含每个项目的 `.ico` 和独立 PNG；它们是从获认可的位图缩放得来，不是原生矢量逐级手工优化版。

### Windows — MSIX / Store（需要时）

- `AppList.targetsize` 输出尺寸：**16, 20, 24, 30, 32, 36, 40, 48, 60, 64, 72, 80, 96, 256px**；并包括默认、浅色、深色资产命名变体。
- `Square44x44Logo` 和 `Square150x150Logo` 最低建议具备 100%、200%、400% 尺寸；另附常用 `StoreLogo` 和 `MedTile` 资源。
- 本包列出了上面资源的设计要求，但 **尚未生成完整 MSIX 资源，也未完成 MSIX 清单、Microsoft Store 上架所需全部宽/大磁贴、启动画面与商店审核**；实际所需根据使用的打包类型检查。

### macOS — 安装包/Dock

- 保留 **1024 × 1024** 的高分辨率视觉母版，常规尺寸准备 16/32/64/128/256/512/1024px。
- 本包提供 PNG 与传统 `.icns` 兼容文件，适合预览、旧版常规分发工作流。
- **新 Apple 图标规范偏向未预先加圆角的方形分层素材和系统遮罩（Liquid Glass）**。从已圆角化展示位图提取的图标不是标准分层源文件；应根据最终源设计另建 Icon Composer 或 Xcode Asset Catalog。

### Android — 启动器 Adaptive Icon

- 需要 **foreground/background** 两层，支持主题模式时配 **monochrome** 单色层；基准 108 × 108dp，核心安全区 66 × 66dp，四周各 18dp 可被遮罩/动画利用。
- 设计时图层应无预裁切圆角；前景主体必须在圆形、圆角方形、不规则系统遮罩下仍可辨认。
- 本包 `Adaptive_Reference_Not_Production` 从现有单层展示位图自动分离图层，仅用于方向评审；**不能未经修正直接当成发布合规源文件**。
- 保留旧密度 mipmap 参考：48/72/96/144/192px。

### Android — Google Play 商店资源

- 独立商店资源 **512 × 512px、sRGB、32-bit PNG、≤1024KB**，完整方形、不自行添加平台级圆角和系统级阴影。
- 本包 `GooglePlay_512.png` 使用重新推定的全幅背景补全供上架前预审；必须检查遮罩效果和细节一致性，不能把透明圆角展示版当成原生商店图标。

## 06. 校验与批准流程

1. **源资产确定**：统一记录被认可图片、版本/日期及原始可编辑分层文件；禁止从截图不经确认直接替换产品正式图标。
2. **语义审查**：是否一眼能识别项目功能；相似产品间是否足够有区别。
3. **视觉审查**：家族底板、色温、主形粗细、留白、阴影与高光是否一致；显著局部炫光不通过。
4. **小尺寸审查**：16/24/32/48/96/256px 实际观看，并在深浅桌面背景下检查；不能仅凭 1024px 大图判断。
5. **平台审查**：Windows ICO/MSIX、macOS 图标资产与 Android Adaptive/Google Play 必须分别验证。
6. **工程审查**：格式、alpha、ICC/sRGB、密度路径、资源引用、安装包图标、升级保留旧 ID、数字签名打包/发布流程。
7. **变更管理**：正式版本替换须获得项目授权、核对历史图标与 App ID、保留备份与校验散列，不得静默更新 ADS 正式条款。

## 07. 源文件与阶段界限

- 当前包来自已认可的**图像成稿**，不是由设计人员提供的 SVG / AI / Figma 可编辑源文件。尤其语匣与缄桥的原始图片是两图并排展示，分离后的 1024px 是从约 500px 的位图上采样，不能宣称新增细节或原生 1024px 清晰度。
- Windows PNG/.ico、传统 macOS .icns 等资源可供开发预览或阶段性测试；正式发版前仍须在目标平台作可视化验收。
- 需要真正全平台正式应用图标时，下一阶段应按此规范 **重建矢量母版**，保留独立底板和主体结构层，再从源文件一键生成所需尺寸。当前被认可版本的中心符号和色系不应被擅改。
