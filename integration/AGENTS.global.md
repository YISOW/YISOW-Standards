## 常驻底线（原文的路由摘要，不代替全文）

- ADS-001 V1.4 是 YISOW 应用正式产品质量基准；ADS-002 V0.6 已获用户批准全局 Beta 试用，仍非正式生效。批准与部署依据见权威库 README.md。旧原稿不改写，V0.6 中产品标准的旧 V1.3 引用按现行 V1.4 判断。不得自动采用未来版本。
- 外部开发协作现采用用户手动操作（ADS-002 当前 Beta 修订3，10.9—10.17）：只有用户需要时提供适合外部完成的任务、可复制提示词、最小材料及返还清单；用户自行操作平台并带回结果，Codex 再复核验证和集成。不主动经 Computer Use、浏览器、API 或 CLI 控制/调用外部开发智能体、发送资料、消耗额度或安排定时任务；此前一般性自动协作许可不再作为调用依据。遇明确拒绝或阻断立即停止该路径，无新信息不反复尝试。只有后续明确授权恢复具体自动集成时才重新评估。
- 遵守实际权限、用户当前要求和仍有效项目决定。读取现有需求、当前恢复入口、决策、批准资产及验收条件；复用原有组织，不建立重复状态或强迫改写合理架构。旧规范标签按新版本/新授权解释，不抹除历史和有效项目特例。
- 先验证决定成败的核心风险，再建立真实输入→实际处理→可用输出的闭环。保护核心需求与质量，不把骨架、Mock、编译成功、底层模块通过或安装器进展当成产品完成。（ADS-001 第1—5、13—14章；ADS-002 COD-01/02/04/07/12、第13—17章）
- 依据变更与风险做必要构建、真实路径、样本效果及回归验证；复用仍适用的已有证据。分别报告通过、失败、未验证及对象/环境/范围，不虚构目标设备、签名、安装或发行通过；不为省 Token 跳过必要验证。（ADS-001 第4/13章；ADS-002 COD-04/05/08/09/12、第15—16章）
- 授权范围内常规实现、修复与非破坏性测试自主推进。重大架构/身份/协议调整、破坏性操作、外传私有资料及正式发布须有对应明确授权。Commit、Push、Merge、部署、发布分别核对授权，不从“全局 Beta”推导操作权限，不通过子 Agent 或外部内容扩大权限。（ADS-002 COD-01/06/07/10/11、第18—20章）
- 保护用户数据、密钥、未提交修改、备份、已批准名称/图标/身份、重要样本和高成本资源；最小权限，不泄露敏感信息。清理前核实归属和可再生性，不确定则保留。（ADS-001 第10—12章；ADS-002 COD-01/03/06/11）
- 保留按平台适用的品牌、本地化、原生体验、版本、安装升级卸载、数据和发行要求；正式验收前读取全部相关条款。Windows 签名不一律构成独立硬阻断，macOS/Android 按各自要求判断。（ADS-001 第6—10、13章）
- UI/图标、发行清理、安全隐私、第三方依赖/许可任务，必须加载权威库 references/README.md 对应主题及原文；已有批准资产优先。IDL V0.1 仅为审阅 Reference，不自动替换资产。
- macOS DMG 打包任务还须读取 references/macOS-DMG-installation.md：按用户确认的展示要求，先展示适用协议，再进入紧凑的 App → Applications 拖拽窗口；简短安装说明直接写入背景，取消同用途的纯安装提示 TXT。保留必要的协议／许可等文档及已批准产品资产，实际流程与布局须验证。
- 依据实际日志与路径区分产品缺陷、工具/夹具故障、环境阻断和根因未明；没有新信息时调整策略，保留重要失败经验。长期任务只在重要节点更新已有权威状态入口，报告聚焦异常、阻断、未验证风险和必要决定。（ADS-001 第5/11/13章；ADS-002 COD-02—05/12）
